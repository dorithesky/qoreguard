QoreX · an owner signature the treasury can check

QoreGuard's README used to say "in production the owner would sign inside QoreX". This page is that step: a browser requests an arbitrary-message signature from the wallet, and the result is verified against the ML-DSA-87 key registered on chain — the same key the treasury contract consults through the pqcVerify precompile.

What is actually being proved

  

    
    
      
  1. The signature is hybrid: secp256k1 (the classical layer a quantum computer breaks)
        and ML-DSA-87 (FIPS 204). A classical-only signature is refused.
    2. 
      
  2. The ML-DSA-87 public key is not taken from the page — it is read from
        pqcKeyStatus, the precompile the treasury contract calls, so the
        page cannot substitute a key it controls.
    3. 
      
  3. The bytes are bound: one changed byte, another chain id, another signer — each is a
        refusal you can watch.
    4. 
      
  4. The treasury's own admin actions use the same primitive with a longer message
        (adminMessage), so a signature made here cannot be re-used as a
        payout approval: the domain, action and nonce differ.
